2. 流程目标

合同审核与审批在商机测试通过后进入。销售发起合同并提交数据组审核，CRM 上线后须将关键参数（合同折扣、预付/后付方式、套餐信息等）填写在流程中并上传合同文件，审批人无需翻查原文件。审核按四方分工拆分——数据组审核参数完整性与账单系统录入，业务管理审核政策合规，法务审核合同条款，主管最终核价并确认特殊条款。OA 逐级审批在 CRM 上线前后均在系统外完成，CRM 仅记录审核面板与审批结果回填。

4. 详细步骤

4a. 四方审核分工

审核方审核内容要点
数据组参数完整性与账单系统录入录入是放行合同的前置必查项，未录入不放行；如遇状态缺失，回溯商机状态获取步骤排查（见 6.4）
业务管理（销售负责人/业务线负责人）政策合规审核折扣、结算方式等是否在授权范围内
法务合同条款审核合同条款合法性与风险
主管（销售负责人/事业部负责人）最终核价 + 确认特殊条款最终核价并确认特殊条款

步骤 销售 数据组 业务管理 法务 主管
1.1 销售发起合同，提交数据组 C I — — —
1.2 CRM 填单：关键参数（折扣/预付后付/套餐）+ 上传合同文件 C I — — —
1.3 数据组审核参数完整性+账单录入 I C — — —
1.4 业务管理审核政策合规 I — C — —
1.5 法务审核合同条款 I — — C —
1.6 主管最终核价+确认特殊条款 I — — — C
1.7 数据组在 OA 发起审批（CRM 上线初期不自动对接） I C — — —
1.8 OA 审批完成→结果回填 CRM+合同扫描件上传 I C — — —
1.9 销售下载合同→客户侧签署 C — — — —
1.10 订单状态更新为「已签约」 I C — — —

R=决策 A=审批 C=执行 I=知会。OA 审批提交权限仅限运营与架构师（SA），销售不直接向 OA 提交合同送审。

环节处理方式说明
OA 审批与签署留线下/人工回填OA 审批与签署在 CRM 系统外完成；CRM 上线初期与 OA 暂不对接，数据组核对关键参数后在 OA 发起审批，完成后回填 CRM

OA 提交权限仅限运营与架构师销售不直接向 OA 提交合同送审，由运营数据组统一管理
审核面板按角色配置CRM 上线后按角色配置审核面板，各角色仅查看与本职责相关的参数
账单系统暂不对接CRM 与账单系统暂不对接，账单系统录入由数据组人工执行
必须留痕节点系统留痕关键参数、四方审核结论、OA 审批结果、合同扫描件、订单状态均须留痕

7. 异常分支

  • 账单系统未录入：未录入不放行合同，为前置必查项。
  • 关键参数缺失：销售须在 CRM 填单时填写完整关键参数（折扣/预付后付/套餐），审批人无需翻查原文件。
  • 审核不通过：退回销售修改后重新提交，审核不通过的合同不得进入 OA 审批。
  • 状态缺失需回溯：如遇状态缺失，回溯商机状态获取步骤排查（见 6.4）。
  • 超常规折扣/非标交付/特殊结算：由管理层决策，按事项级别分别由区域销售负责人/业务线负责人/事业部负责人审批。
