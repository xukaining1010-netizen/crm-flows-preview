2. 流程目标

续签管理覆盖各业务线存量客户的合同到期续签流程。销售须在合同到期前 90 天启动续签跟进，至少完成 2 次客户沟通。到期前 30 天仍未反馈续签意向的视为不续签。Cloudflare 有原厂强制规则（提前标记流失风险、自动建档 CIO）。

3. 输入输出

项目内容
触发条件合同到期前 90 天（系统/数据运营触发提醒）
上游流程签约与追踪（flow-01-4）→ 服务中商机到期提醒
下游流程续签成功 → 重新进入服务中；不续签 → 运营按不续签口径处理
产出物续签意向记录、续签合同（如成功）、不续签标记（如失败）
关键字段合同到期日、续签启动时间、沟通次数、续签意向、流失风险标记

4. 详细步骤（泳道表 · RACI）

步骤 销售 运营组 销售负责人
1.1 合同到期清单维护 C I —
1.2 到期前 90 天启动续签跟进 C I —
1.3 至少 2 次客户沟通 C — —
1.4 到期前 30 天判定续签意向 C A R
1.5 CF: 原厂标记流失风险 → 运营转达 — C —
1.6 续签成功/不续签处理 C A I

R=决策 A=审批 C=执行 I=知会

环节处理方式说明

7. 异常分支

  • 到期前 30 天无反馈：视为不续签，运营按不续签口径处理（CF: 默认按不续签回复原厂）。
  • CF 原厂未提前通知流失风险：按原条款自动续约。
  • AWS 续约：须重新核定单价与超量单价，对外口径须与内部一致。
  • 框架协议类（如阿里框架协议）：续签须先经法务审核。
  • CF 续签商机：由原厂自动建档、默认按 CIO 处理，报备后由原厂关联为 PIO。

8. 关键控制点

类型控制点动作/后果
可核查到期前 90 天启动续签跟进至少完成 2 次客户沟通
可核查合同到期清单维护区别于商机有效期，销售须维护所辖客户到期清单
可核查续签成功/不续签记录续签结果须留痕，不续签由运营按口径处理
